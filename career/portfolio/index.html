フリーランスエンジニアのポートフォリオ作り方

フリーランスエンジニアのポートフォリオは「プロフィール・技術スタック・実績（課題→対応→結果）・個人開発/GitHub・稼働条件と連絡先」の5項目を1ページにまとめれば十分です。守秘義務のある案件の書き方、GitHub Pagesなど無料の公開先の制限まで整理します。

最終確認日：2026年11月17日

フリーランスエンジニアのポートフォリオは、①プロフィール ②技術スタック（経験年数つき）③参画実績（課題→自分の担当→結果を数字で）④個人開発・GitHub・技術記事 ⑤稼働条件と連絡先、の5項目を1ページにまとめれば十分です。エージェント経由の案件ではスキルシートと面談が主な判断材料なので、ポートフォリオはスキルシートの裏付け（URLを記載）として作ります。守秘義務のある案件は、社名・固有の数値を伏せて「業界・規模・期間・役割・技術」で書き、公開してよい範囲は契約書で確認します。公開先は GitHub Pages・Vercel・Netlify などの無料枠で足ります。

詳細ガイド（全4セクション）

1

フリーランス向けポートフォリオの目的

フリーランスエンジニアのポートフォリオは、クライアントやエージェントに依頼したいと判断してもらうための、技術力・実績の証明となる資料です。転職向けとは異なり、即戦力であることを示すことが重要です。

2

ポートフォリオに載せるべき内容

過去の担当プロジェクト概要、使用技術スタック、自分が担当した役割と成果、個人開発プロダクト、GitHubリポジトリのリンクを掲載することをおすすめします。

3

GitHubプロフィールの整備

コードの質を示すために、GitHubのREADME・コミット頻度・リポジトリの整理が重要です。個人開発アプリのリポジトリを公開することで技術力を可視化できます。

4

ポートフォリオサイトの作り方

Next.js/Reactなどで自作することで技術力のアピールにもなります。無料で始めるならGitHub Pages、Vercel、Netlifyが使えます。デザインよりも内容の充実を優先することをおすすめします。

ポートフォリオに載せる5項目と書き方

発注者やエージェントが確認したいのは「この人に任せて、いつから・どの条件で・何ができるか」です。項目を増やすより、次の5項目を1ページで読める形にまとめます。実績は全件を並べず、応募先の案件に近いものを厳選して深く書くほうが伝わります。

項目書く内容書き方のポイント
① プロフィール氏名（屋号）・肩書き・エンジニア歴・得意領域冒頭の数行で「何ができる人か」が分かるようにする
② 技術スタック言語・フレームワーク・クラウド・DBと、それぞれの実務年数スキルシートと年数・名称をそろえる（食い違うと面談で確認される）
③ 参画実績案件の概要・チーム規模・期間・自分の役割・使用技術・結果「課題→自分が担当したこと→結果」の順に。結果は処理時間・件数・工数などの数字で書く（公開できる範囲で）
④ 個人開発・GitHub・技術記事動くデモのURL、リポジトリ、Qiita/Zenn などの記事READMEに目的・構成・工夫した点を書く。完成度より設計の意図を説明できること
⑤ 稼働条件と連絡先稼働可能日数・開始時期・リモート可否・連絡先問い合わせ先はページ上部とページ末尾の両方に置く

※ 項目の構成は当サイトの整理。競合の解説記事（@SOHO「フリーランスのポートフォリオの作り方」2026年8月19日更新ほか）も、実績を「課題→アプローチ→結果」で数字を添えて書くこと、厳選して載せることを勧めています。

守秘義務（NDA）のある案件の書き方

業務委託の案件は、秘密保持契約や業務委託契約で、社名・システムの内容・成果物の扱いが決められていることが多く、許可なく公開すると契約違反になるおそれがあります。公開してよい範囲は契約書の秘密保持条項・成果物の権利の条項で確認し、迷う場合は発注者に確認します。なお、2024年11月1日施行のフリーランス法（特定受託事業者に係る取引の適正化等に関する法律）では、発注事業者は業務委託をしたとき、給付の内容・報酬の額・支払期日などの取引条件を書面または電磁的方法で明示する義務があります（公正取引委員会）。明示された内容は手元に残しておきます。

公開できない案件は、特定できる情報を伏せて、次のように書き換えます。

伏せる情報書き換え方の例
クライアントの社名・サービス名「大手EC事業者の会員基盤リニューアル」のように業界と規模で表す
売上・ユーザー数などの固有の数値自分の作業の結果（「バッチ処理の時間を半分に」「テストを自動化して手作業の確認をなくした」など）を、公開してよい範囲の表現で書く
画面・ソースコード載せない。同じ技術で作った個人開発やサンプルのリポジトリで技術力を示し、詳細は面談で口頭説明する

※ 出典：公正取引委員会「フリーランス法特設サイト」（取引条件の明示・2026年11月17日確認）。契約の確認項目は当サイトの業務委託契約チェックリストも参照してください。

無料で使える公開先と制限

エンジニアのポートフォリオは、自作サイトを無料のホスティングに置く方法が一般的です。GitHub Pages は GitHub 公式ドキュメントで使用制限が公開されています。Vercel・Netlify も無料プランがありますが、条件は変わることがあるため、利用前に各社の料金ページで確認してください。

公開先費用公式に公開されている主な制限・注意
GitHub Pages無料（公開リポジトリ）公開サイトは1GB以下、ソースリポジトリは推奨1GB、帯域幅の目安は月100GB（ソフト制限）、ビルドは1時間10回が目安（カスタムの GitHub Actions で発行する場合は適用外）、デプロイは10分でタイムアウト。オンラインビジネス・商用SaaSを主目的とする使い方は対象外
Vercel・Netlify無料プランありNext.js などのビルドとプレビューに対応。無料枠の条件は各社の料金ページで確認
Notion・PDF無料〜コードを書かずに作れる。PDFはスキルシートと一緒に送付しやすい

※ 出典：GitHub Docs「GitHub Pages の制限」（2026年11月17日確認）。

実践的なポイント

  • 1守秘義務があるプロジェクトは概要のみ記載し、詳細は面談で説明する
  • 2個人開発は、完成度よりも技術的な意図を説明できることが重要
  • 3GitHubのコミット履歴は継続的な学習の証拠になる
  • 4技術ブログやQiita/Zennの記事はポートフォリオの補強として効果的
  • 5ポートフォリオURLはスキルシートに必ず記載する

よくある質問

ポートフォリオがなくても案件は獲得できますか？+
エージェント経由ではスキルシートと面談が主な評価軸になるため、ポートフォリオがなくても案件獲得は可能です。ただしポートフォリオがあると競合との差別化になります。
個人開発の経験がない場合はどうすればよいですか？+
OSS（オープンソース）のプロジェクトへのコントリビューションや、業務で使っている技術の勉強リポジトリをGitHubに公開するだけでも差別化できます。
ポートフォリオは何ページくらいが理想ですか？+
1ページ（シングルページ）でプロフィール・スキル・プロジェクト実績・連絡先が揃っていれば十分です。見やすさを重視し、シンプルにまとめることをおすすめします。
守秘義務がある案件は、ポートフォリオにどう書けばよいですか？+
社名・サービス名・固有の数値・画面やソースコードを伏せ、「業界と規模」「期間」「チーム人数」「自分の役割」「使用技術」「自分の作業の結果」で書きます。公開してよい範囲は契約書の秘密保持条項・成果物の権利の条項で確認し、迷う場合は発注者に確認してください。
ポートフォリオサイトは無料で公開できますか？+
できます。GitHub Pages は無料で使え、公開サイトは1GB以下・帯域幅の目安は月100GBなどの制限が公式に公開されています（GitHub Docs・2026年11月17日確認）。Vercel・Netlify にも無料プランがあります。独自ドメインを使う場合はドメイン代がかかります。
